Sujet : Traitement Batch (80M de lignes) & Traçabilité de la Décision

1. Contexte & Enjeux d'Audit

L'exécution du moteur de règles métier sur un lot de 80 millions de lignes répond à une exigence de décision automatique. Au-delà du simple calcul du résultat final, la solution doit garantir une traçabilité complète et inaltérable (auditabilité des décisions).

Chaque décision doit conserver les éléments suivants :

  • Variables en entrée : Données brutes de la transaction / du client.
  • Règles déclenchées (Matched Rules) : Identifiants exacts des lignes des tables de décision DMN appliquées.
  • Sous-décisions intermédiaires : Valeurs calculées aux nœuds intermédiaires du graphe DMN.
  • Résultat final & Horodatage : Décision rendue avec version du modèle DMN et timestamp.

4. Impact de l'Audit sur les Performances Batch

Le niveau d'audit requis impacte directement les performances et la viabilité de la cinématique Spring Boot Kogito :

Axe Audit & Infra Impact Technique (80M de lignes) Niveau de Risque
Volume d'Audit S3 Générer l'audit complet fait passer la taille unitaire d'une ligne de ~100 octets à ~500 octets / 1 Ko. Le volume total d'audit atteint 40 à 80 Go de JSON sur S3. Critique
Saturation RAM (Heap) L'instanciation des objets DMNResult et DMNAuditEventListCollector dans Kogito consomme énormément de mémoire JVM, augmentant le risque d'OutOfMemoryError. Critique
Re-parsing Databricks Le fichier JSON d'audit déposé sur S3 doit être ré-analysé par Databricks pour réintégration dans le Data Lake, entraînant une double sérialisation très coûteuse. Élevé
Traçabilité Native (Delta) En contournant Spark, on perd la traçabilité native du Data Lake (Delta Lake Time Travel et versioning ACID direct). Moyen

6. Recommandation d'Architecture pour l'Audit

Avis d'Architecture :
Le besoin d'un audit fin (sous-décisions + règles matchées) ne justifie pas le passage par une application externe Spring Boot. L'export de 80 Go d'audit en JSON via S3 crée un goulot d'étranglement majeur.

Prochaine étape préconisée :

  1. Conserver la modélisation DMN établie par les équipes métier.
  2. Embarquer le moteur de décision DMN (kie-dmn-core) dans un UDF Spark directement sur Databricks.
  3. Stocker le résultat d'audit sous forme de colonne structurée (StructType) directement dans la table Delta cible.
    Résultat : Performance distribuée x10, zéro transfert S3/JSON et requêtage immédiat pour l'équipe conformité.
