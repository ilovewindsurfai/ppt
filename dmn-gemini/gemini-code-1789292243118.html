Architecture d'Audit Natif DMN pour Spark & Databricks

Synthèse : Remplacement de l'architecture lourde Spring Boot Kogito (fichiers JSON sur S3, risques d'OOM, latence) par un transpiler DMN-vers-SQL natif exploitant les objets STRUCT de Spark. Zéro impact sur les performances, traçabilité exhaustive à l'échelle de 80 millions de lignes.

1. Le Mécanisme Technique (`STRUCT` + Pattern Valeur/Règle)

Le transpiler réutilise les CASE WHEN existants en faisant renvoyer par chaque règle un mini-objet (STRUCT) contenant à la fois la valeur métier (.val) et l'identifiant de la règle d'audit (.rule_id).

-- Exemple de code SQL généré par le transpileur
WITH etape_score AS (
  SELECT 
    *,
    CASE 
      WHEN score_credit < 500 THEN STRUCT('ÉLEVÉ' AS val, 'RULE_SCORE_KO' AS rule_id)
      ELSE STRUCT('FAIBLE' AS val, 'RULE_SCORE_OK' AS rule_id)
    END AS res_score
  FROM source_data
),
etape_decision AS (
  SELECT 
    *,
    -- Le moteur utilise uniquement le .val pour la suite de la logique
    CASE WHEN res_score.val = 'ÉLEVÉ' THEN 'REFUSÉ' ELSE 'ACCORDÉ' END AS val_ decision_finale
  FROM etape_score
)
SELECT 
  id_client,
  val_decision_finale AS decision_finale,
  -- L'objet d'audit complet regroupé en fin de requête
  STRUCT(
    STRUCT(res_score.val AS score, res_score.rule_id AS regle_score) AS sous_decisions,
    ARRAY(res_score.rule_id) AS regles_matchees
  ) AS audit_trail
FROM etape_decision;

3. Utilisation de l'audit dans Delta Lake

-- 1. Inspection simple d'une sous-décision
SELECT id_client, decision_finale, audit_trail.sous_decisions.score 
FROM table_decisions;

-- 2. Filtrage métier avancé sur l'audit
SELECT id_client 
FROM table_decisions 
WHERE array_contains(audit_trail.regles_matchees, 'RULE_SCORE_KO');

4. Prompt pour GitHub Copilot

Utilisez le prompt ci-dessous pour adapter votre transpiler existant :

Agis en tant qu'architecte de données expert en transpilation DMN vers Spark SQL. 
Je souhaite modifier mon transpiler existant pour qu'il intègre un mécanisme d'audit natif 
basé sur des colonnes STRUCT Spark, sans modifier les performances de calcul des décisions.

Voici les consignes d'implémentation pour le code du transpiler :
1. Modifie la génération des expressions de règles (les CASE WHEN) pour qu'elles renvoient 
   un objet structuré contenant deux champs : `val` (la valeur métier utilisée pour la suite) 
   et `rule_id` (l'identifiant de la règle DMN déclenchée).
2. Pour chaque sous-décision intermédiaire du graphe DMN (DRD), conserve le résultat dans 
   une CTE nommée.
3. À la fin de la génération du SQL, ajoute une colonne finale nommée `audit_trail` de type 
   STRUCT qui imbrique l'ensemble des `sous_decisions` et un tableau `regles_matchees` 
   recensant tous les rule_id traversés.
4. Assure-toi que la décision finale de haut niveau utilise exclusivement la propriété `.val` 
   des structures précédentes afin de ne pas perturber la logique métier d'origine.
5. Fournis-moi le code mis à jour des fonctions de génération de clauses SELECT et STRUCT 
   dans mon langage actuel.
